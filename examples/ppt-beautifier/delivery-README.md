# 可选 PPT 交付角色

这是登记目标 `binding.driver=ppt_delivery` 的固定领域实现，不是网关通用 DAG。制作角色 `ppt-beautifier` 的既有合同保留。交付角色自身的持久状态由网关和任务记录一起保存，网关后台调用 `advancePptDelivery` 推进；主会话不轮询。

配置结构见 `delivery-policy.example.json`。目标编号必须对应人工已登记目标，机器路径须按部署实际校验，不因拷贝示例自动存在。`workspaceRoot` 应在各执行宿主共同可读写的临时根内；PPT 公开目录位于制作角色允许目录内。此版本是同机文件交付角色，不能把本机绝对路径当作跨机共享文件系统。

`backupTargets` 可按 `project_script`、`ppt_production`、`independent_review` 指定预登记备用目标，`maxTargetSwitches` 限制整个交付父任务的切换次数。只在原子任务已确认 `failed` 后选择不同的备用目标，另建子任务并保存 `replacesJobRef`、原执行轮次、实际目标、原因与策略版本；父任务目标不变。受理未知、认证缺失、等待超时和失联都不能触发切换。同一目标修复继续原子任务并新增执行轮次；制作恢复同时使用新结果目录。样例备用编号只是配置示例，未登记时应移除该项，不自动创建目标或更改全局模型。

输入为 `projectDirectory`、`projectName`，可选 `instructions`，页数固定为六页。`revisionRequest` 是调用方预先指定的一次显式改进，用于验证同一制作子任务的新执行轮次；该轮单独计入 `acceptanceExerciseRevisions`，至多一次，不占 `maxRevisionRounds` 的质量修订预算，也不能记为真实质量缺陷。项目只读，合同和执行证据只写任务目录，只有八份产物进入公开目录。

固定流程：项目总结和六页脚本子任务 → 制作子任务 → 代码确定性校验 → 独立会话复核子任务 → 有限返工或交付。阶段间结束 ACP 对话轮次不改变父任务 `working`，等待阶段用 `waiting_children` 表达。制作返工在同一子任务继续并新建执行轮次，每次制作输出隔离到新版本；独立复核始终是另一个子任务。父任务执行轮次不因此增加。

`execution_get` 的 `deliveryProgress` 返回当前阶段、各阶段状态、已完成/未完成阶段及 `availableResults`。这些是持久执行事实的查询投影，阶段完成不会创建主会话通知或唤醒。制作端完成、机器校验通过、独立验收通过分别记录；结果按版本留存，后续返工不会隐藏前一版已校验产物。制作端回执只提供文件校验时标为 `producer_host_verified`，父流程实际机器校验后才标 `machine_passed`；只有合同要求的最终验收通过且父任务完成，`deliveryReady` 才为 true。

失败、需输入或取消的通知会汇总已完成/未完成阶段，并附上最新已有版本的 PPT 与预览链接。未通过最终验收的文件标为“已有 PPT（未完成最终验收）”，不会冒充最终交付。已经投递或 ack 的历史通知保持原文和编号，不因增加进度查询而重新唤醒；历史任务可以通过 `execution_get` 查看保留的产物。

父任务关闭使用 `execution_cancel`：`{"originSessionId":"实际原会话","jobId":"父任务编号"}`。PPT 交付默认级联其子任务；`cascade:false` 会被拒绝，防止协调器停了但委派执行继续运行。通用 A2A 任务默认仅关闭本任务，可显式 `cascade:true` 关闭后代任务。关闭意图先持久化，阻止关闭任务及其子任务的后续派发/继续，再等待在途派单返回并取消实际后端执行。已完成的任务及产物保留，取消一个子任务不会取消它的父任务或兄弟任务。

`cancellation.status` 为 `pending / blocked / completed`，附带逐执行轮次的后端状态。受理未知、断连或取消未确认时保持 blocked，并在重启后继续核对；不能据此声称全部停止。PPT 父任务只有在已知子执行均终结后才变为 `canceled`；历史 completed/failed 终态不改写。关闭后不再进行阶段推进、修订或备用切换，重复关闭幂等。最终取消/异常通知仍由原机制投递，业务接受与通知 ack 继续分开记录。

机器校验实际检查严格八项 manifest、私有/公开/HTTP GET 字节、ZIP 完整性、六页 16:9、各页原生形状和可编辑文字、PNG 签名，以及与最终字节一致的实际 finalizer 原始回执。它不证明文字事实或视觉质量。独立复核必须自己查看总览和全部六页大图，核对脚本与源码，将事实与视觉结果绑定到清单摘要；制作自评不替代独立复核。发布前再读一次产物并校验摘要，检查项目基线与脚本来源未变化。

派出任何模型子任务前，交付角色先写入临时 PNG，并通过合同采用的 `/artifacts/<jobId>/revision-N/<file>` 路由真实 GET 比较字节，再移除探针并记录 `publication-preflight.json`。本目录的产物服务同时支持旧的两段地址与该三段版本地址；不开放任意嵌套目录，并逐级拒绝符号链接。必须同步部署此产物服务源码，仅更新网关不能证明版本链接可用。发布端 HTTP 404、超时或下载字节不符转为 `input_required`，不能消耗内容修订预算、让制作模型反复导出相同内容。修复前置条件后可按新任务显式关联 `replacesJobRef` 重测；本版本不自动重开已经终态的交付父任务。

协调状态中的 `pending` 在提交前持久化，客户端编号稳定。已知终态失败才能有限恢复；未知受理立即停止新派单等待核对。断连只推迟查询，不能证明停止。时长耗尽保留在途状态，不假称取消。不更改宿主全局模型或其他目标。父任务完成不等待通知 ack 或人工接受。`parentUpdatePending` 用于崩溃后补记父结果和通知；后台必须同时恢复 `working` 或有该待处理项的协调运行，通知按父任务执行轮次/结果版本幂等投递。

对因旧策略停止、但已取得独立验收 `passed` 的失败父任务，可显式启用目标的 `continue` 能力并以 `execution_continue`、`input: {}` 恢复：同一父 Job 新建执行轮次，原失败轮次保持终态。只接受无在途/未知子任务的已通过停点，冻结输入、宿主与角色不变；沿用原工作目录，新写恢复合同，保留累计成本、质量预算及总时长预算。恢复后先重新检查源码快照、产物字节与原验收摘要，匹配才继续。既有子 Job 不改变创建时的 `parentAttemptId`，其复用另记在新父轮次的 `recovery` 中；新增独立复核子任务关联新父轮次。

若父轮次在独立验收阶段失败，但已有机器校验通过的成稿及冻结脚本/来源清单，可显式只重试验收：

```json
{"method":"execution_continue","params":{"originSessionId":"实际原会话","jobId":"原父任务编号","clientRequestId":"本次恢复稳定编号","input":{"recoveryMode":"review_only","reviewTargetId":"已登记的独立验收目标"}}}
```

该模式创建新父执行轮次和新的独立验收子 Job；复用原版本、产物摘要、脚本和制作结果，保留原失败轮次与报告。仅新验收轮次的执行重试计数归零，有界次数仍沿用冻结策略；本轮时长预算从显式恢复开始，历史累计耗时继续记录，质量修订预算不重置。不会自动切换其他验收目标、进入制作或质量返工；阻断问题返回 `input_required` 并保留已有产物。新报告、交付回执、发布预检记录以新父 attemptId 单独命名。提交前、交付前均核对来源和真实 HTTP 下载字节，报告绑定原产物摘要，并检查制作与验收不是同一会话。

项目已更新时，可在上述 input 显式增加 `sourceSnapshotDirectory`：该目录必须还原原 `source-manifest.json` 的全部引用文件；系统逐一核对路径边界和原 SHA256，不修改来源清单，也不把当前源码当成原稿依据。无法还原、脚本/来源清单/产物改变均停止且不派验收。关闭或已取消父任务禁止恢复；存在在途、受理未知或未决后代时也拒绝。历史失败通知保持原记录，最终交付仅为新轮次产生通知。其他失败或等待输入的停点仍不能自动重开。

验收记录包括提交、继续、后台查询、子通知 ack、机器校验次数、独立复核轮数、质量返工与显式演练轮数、累计耗时。模型 token/费用在后端不提供可靠数据时写 `unknown`，不能用主会话步骤减少推导总成本下降。主会话步骤数应从真实会话工具调用记录统计，区分开发部署成本与服务已就绪后的派单—回执—接受—ack 成本。

测试：在 `packages/service` 下运行 `node --import tsx --test test/ppt-delivery.test.ts`。

## 主会话调用必须交接

开发、部署、预检与回归在正式派单前独立完成。主会话按包内 `skills/acp-service/references/async-caller.md` 的限定入口调用：dispatch 后立即结束本轮，禁止主动 get/list/inbox 轮询、等待完成、读子会话日志或重复 QA。后台协调器持久推进，只有真实通知进入原主会话后才 inspect → record → ack；ack 同一操作完成原生调用计步，随后立即答复。额外调用一律计入，不因属于调试而从正式窗口删除。该规则约束调用技能与入口，不声称通用查询 API 已被全局禁用。
