## 设备容量与自动任务排队

- 新增设备共享的容量账本、跨进程原子准入与持久 FIFO：任务启动瞬间检查当前可用内存，扣除可配置的系统/用户保留余量和启动期预占；同时约束自动软上限与最终硬上限。macOS 读取可回收页估计可用空间，默认单实例预算 1 GiB；CPU/总内存仅用于并发阈值估算，不替代实时判断。
- 资源不足的 A2A 自动任务保持 `SUBMITTED / Pending`，内存或名额释放后按入队顺序补位；取消移除队项。会话准备后和 DSH 提交 prompt 前复检，不足时复用已准备会话重新等待，不重复建会话或提交模型任务。同上下文等待取消无需等内存恢复，且不会让后继绕过前序。
- 取消信号传入后端会话准备，取消等待初始化清理完成；DSH 会话原生关闭会中止尚在等待的启动检查，不会留下内存恢复后的迟到 prompt。DSH 宿主已经创建的空白会话记录保留，不擅自删除原生历史。
- ACP `new/load/resume/import` 传递 SDK 取消信号，客户端尚未取得新 ID 时也可撤销内部启动；取消已有 live 会话的附着保留原用户 handle/turn，且不关闭后来接管者。接管通知在附着成功后发出，避免撤销附着误伤原用户。
- DSH 新建 ACP 会话后，如果初始配置或绑定保存失败，先确认关闭本次新会话再结束连接，避免遗留进程耗尽容量。远端关闭无法确认时保留原身份及恢复标记，阻止同一会话重复新建；已有绑定不进入新会话失败清理路径。
- ACP 服务的实际进程、兼容探测和预热同样进入受控进程队列；任务/进程分开计并发，启动内存预算共享。修复 runtime 获准启动后被取消、未生成 PID 时缺少失败回调而泄漏名额的问题。原生应用中用户自行启动的会话不经自动队列；其内存占用影响下一次实时准入。
- 活进程不按 TTL 清除；owner 已退出但子进程仍活着或启动结果未知时保守占位。队列保存顺序，不改变 A2A 重启后标记中断且不自动重跑的既有语义。策略、配置和边界见[容量与队列说明](../docs/device-capacity-queue-20261023.md)。本轮尚未部署至共享宿主，旧运行进程未追溯纳入计数。
